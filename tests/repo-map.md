# repo-map — tests/

The pytest suite. Every test drives the Runtime and the Job supervisor at their process/CLI seam against the hermetic fake provider — never with SDK-level mocks, never with a mocked process layer, and never against a real endpoint (ADR 0011).

- `fake_provider.py` — the test bed, not a test: `FakeProvider` (a `ThreadingHTTPServer` on an ephemeral port serving `POST /v1/messages` as SSE from a scripted turn list, recording every request's body and headers) plus the script builders `turn()`, `text_block()`, `tool_use_block()`, the turn-gate seam `gate(index)` (holds the worker between two turns — records the request, sets `reached`, blocks until the caller sets `release` — the window a steer test writes into), and the fault builders `status_fault()` (any status, body and headers, e.g. `Retry-After`), `hang_fault()` (stall mid-turn, optionally after a half-served block), `ping_fault()` (keepalives and SSE comments only), `eof_fault()` (clean close before `message_stop`), `stream_error_fault()` (an `error` event inside a 200) and `drop_fault()` (connection closed with no response).
- `conftest.py` — shared fixtures and scripts: the autouse `keyless_home` (temp `HOME`, synthetic `model-keys.env`, ambient `ANTHROPIC_*` removed), `start_fake_provider`, and `job_env` — a `JobEnv` factory that binds a Profile to the fake through the real overlay path and runs a Job via `main(["exec", ...])`, or via `run_exec` when a `LoopConfig` is injected. `JobEnv` also exposes `result()`, `observations()` (every tool_result from the durable Thread) and `tree()` (the workspace contents, walked without following symlinks). Also holds the shared `BASH_COMMAND`/`REPORT_PAYLOAD` constants, the script builders `bash_then_report_script()`/`tool_script()`/`bash_script()`, `tool_results()`, the `OMIT` spec sentinel, the `write_overlay`/`write_keys` helpers, and the supervision seams — `Sleeper` (records backoff instead of sleeping), `SteppingClock`, `identity` jitter, `loop_config()`, and `reporter_events()`/`events_named()` for reading the reporter's JSON lines back out of stderr. It also holds the dispatch seam: the `dispatch_env` factory and its `DispatchEnv` (a workspace whose state root is a temp `CLAUDE_PLUGIN_DATA`, with `bind()` for a second Profile, `dispatch()` running the real `task` verb, and a `reap()` teardown that waits out every worker it started and pid-start-time-guards any SIGKILL), plus the `wait_for()`/`wait_for_status()` polls. And the lifecycle seam: `build_record()` (publish a record directly, for the states a live worker will not hold still in), `write_artifacts()`/`job_artifacts()`/`job_leftovers()` (the six per-Job artifacts, a nested steer `consumed/`, and a name-prefix sweep that catches a seventh), `aged()` (an ISO timestamp N seconds in the past, so a 60 s grace costs nothing), `dead_pid()` and `assert_wire_shape()` (no consecutive same-role messages, every `tool_use` answered).
- `test_fake_provider.py` — the harness itself: a scripted text turn is valid SSE for a raw SDK client.
- `test_walking_skeleton.py` — the loop: bash then report_result, the tool_result returned to the provider, the tool-less-turn nudge (parametrized over three stop reasons), bearer auth with the exact advertised tool list, and report_result sharing a turn with a sibling tool_use.
- `test_transcript.py` — the Thread: replaying the JSONL reconstructs the history, and the outgoing delta is on disk before the request that carries it.
- `test_spec.py` — job-spec validation fails fast (missing field, wrong type, unknown key, non-existent workspace, and a bad `inactivity_timeout_s`/`ladder_attempts` override) with no request reaching the provider.
- `test_liveness.py` — the supervision layer: a mid-stream hang retried (bounded in elapsed time, so a watchdog that never breaks the read fails), ping keepalives failing to mask that hang, 429 and 5xx clearing within the ladder with the exact 5/10/20 backoff, the classification table parametrized row by row, `Retry-After` floored then clamped, ladder exhaustion (six requests, five sleeps, nonzero exit, provider body preserved), the nullable inactivity payload, a 401 failing fast, and transcript atomicity across the two decisive half-stream shapes.
- `test_no_caps.py` — 120 turns under a clock that jumps four and a half hours per read still complete, and `LoopConfig`'s field set matches an exact allowlist so no cap can be added under any name.
- `test_profiles.py` — the five shipped rows, overlay merge and field-level partial merge, shell-quoted key resolution, and the missing-profile / unknown-profile / missing-key fail-fast paths.
- `test_tools.py` — the rich set end to end: a happy path per tool against a real temp workspace, apply_patch's all-or-nothing rejection, and a raising tool (undecodable file, invalid regex) becoming an observation the loop continues from.
- `test_confinement.py` — containment and the denylist: absolute / `..` / symlink escapes, an in-workspace symlink still usable, the sibling-prefix case that a `startswith` check would pass, a directory symlink not followed by grep/glob/list_dir, every denied command family (parametrized), and the quoted-argument false positives that must still run.
- `test_bash_timeout.py` — expiry is an observation carrying the output so far, the backgrounded descendant dies with its process group while the Runtime survives, and every invalid `bash_timeout_s` (parametrized) fails spec validation while omission resolves to 600 s.
- `test_readonly.py` — the read-only posture: write tools absent from the advertised schema, a filtered-out or unregistered tool refused at dispatch, write-shaped bash blocked, and reads (including `2>&1` and `2>/dev/null`) unaffected.
- `test_dispatch.py` — detached dispatch: the id returned in under a second, the worker surviving a SIGKILL of its dispatching shell's whole process group, state readable from a fresh process afterwards, a genuinely failing spawn (a non-executable interpreter, no mocked process layer) marking the Job `failed`, the pid-write CAS losing its race harmlessly, a second claimant and a pre-claim cancel both exiting without running, `--bash-timeout-s` actually cutting a command short, runtime/03's failure payload rendering onto `errorMessage` with the full JSON in the log, and a raising reporter never failing the Job.
- `test_status.py` — `status`: phase and progress preview while running then completed and listed exactly once, `--wait` returning within ~2 poll intervals of completion, `--wait` waking on new LOG lines with status and phase held still, every non-terminal return exiting 2 (progress wake-up and expiry alike) against 0 only when terminal, `--timeout-ms` clamping, and a named-but-missing Job exiting 1 against an empty store.
- `test_logs.py` — `logs`: the spawn log surfaced whenever the progress log is empty or absent (parametrized over queued/failed/running, since the crash it exists for leaves the record `queued`), the progress log printed and `--tail`ed, and control characters escaped so one event is always exactly one line.
- `test_state.py` — the durable store: the index rebuilt from record FILENAMES with a `<id>.result.json` beside a record still rebuilding to one Job, a subdirectory dispatch resolving to the repo's single state dir, state-root resolution with empty and relative values counting as unset, 0700/0600 across every artifact, `/proc/<pid>/stat` field 22 parsed past a comm carrying spaces and parentheses, `schemaVersion` present and unknown/missing fields tolerated, the absence of any session-keyed reap or CLI selector, and `resolve_job` refusing a miss or an ambiguous prefix.
- `test_concurrency.py` — two simultaneous dispatches (on two Profiles) both complete, `state.json` parses AND carries both ids, and each record keeps its own title, profile, pid, log and transcript.
- `test_result.py` — `result`: a completed Job's exact stored payload rendered field by field and `--json` emitting the stored artifact's bytes, an active Job exiting 2 with guidance to status against an unknown id exiting 1, and a payload-less terminal Job (failed, and derived-interrupted with its pointer to resume) still exiting 0.
- `test_cancel.py` — `cancel`: the worker AND the bash child it started in its OWN session both dead afterwards with the record cancelled and reasoned, two active Jobs refusing an id-less cancel by listing both (then each cancellable by name, then "no active Job"), and a Job that completes DURING the kill keeping its status and result through the compare-and-swap.
- `test_resume.py` — `resume`: the resumed Job's first request carrying the source's full history including its terminal `report_result` answered synthetically, the follow-up merged into that trailing user turn, the source's Thread intact on disk, Profile and write posture inherited; a refusal, creating no Job, while any Job is active; and the bare form taking the newest resumable Thread with the default follow-up while a named-but-unknown target still exits 1.
- `test_stale.py` — crash detection: a SIGKILLed worker reading as `interrupted` with the record still stored `running`, `status --wait` returning at once with 0, and its Thread still resumable; a `queued` record with a dead pid grading interrupted only once the heartbeat is aged past the grace; and resume normalizing all three transcript tail shapes (torn final line, unanswered `tool_use`, trailing user turn) into a history the provider accepts.
- `test_prune.py` — pruning: a dispatch and the worker's terminal transition dropping the oldest finished Jobs with all six artifacts (steer `consumed/` tree included) and clearing them from `state.json`, and running plus interrupted Jobs surviving untouched without consuming a slot.
- `test_steer.py` — the steer queue: a steer written at the turn gate landing on the next request's single user turn (marker included, no consecutive user messages); multiple steers injecting in write order exactly once each with all three acknowledged into `consumed/`; a steer queued for a confirmed-dead worker injected by the relaunched (reclaimed) `task-worker` before the first API call; a crash in the flush→rename window (via `STEER_ABORT_VARIABLE` in a real subprocess) still yielding exactly ONE delivery across both runs (guarding the zero-delivery seeding failure); two writers pinned to one epoch-ms via `STEER_CLOCK_VARIABLE` both surviving on distinct random suffixes; the drained steer stamped in the Thread (id + enqueue-ts metadata) and the log (timestamped); terminal / interrupted / unknown / ambiguous / empty-message refusals all exiting 1 and writing no file; and a steer that lost the accept-versus-terminate race swept and logged undelivered at exit.
- `test_plugin_manifest.py` — surface/01's install contract: both manifests live under `.claude-plugin/` and parse, plugin name is `chinamax`, marketplace name is kebab `deepseek-plugin`, `owner.name` present, the sole `plugins` entry self-sources `"./"`, and its version equals `plugin.json`'s (the full marketplace-add + install is verified manually — the machine's `claude` CLI cannot be driven non-interactively here).
- `test_bridge_contract.py` — the Bridge contract's required stanzas asserted as whitespace-normalized prose presence (Bash-only + sonnet frontmatter, profile-required refusal with all five Profiles, the prohibition block, untrusted-data rule, stdin/quoted-heredoc transport, the `--timeout-ms 90000` poll branching on the exit code, verbatim `result <id>`, steer/resume mappings incl. the finish-during-steer re-route, explicit-id resume, and the bounded relay-then-stop rule). The recorded exception to "never test markdown prose"; behavior is proven in `test_bridge_path.py`.
- `test_bridge_path.py` — the Bridge's command SEQUENCE driven as real `python -m chinamax` subprocesses against the fake provider (not the markdown): dispatch detaches and its poll distinguishes still-running (exit 2, progress surfaced) from terminal (exit 0) before `result` returns the stored payload verbatim; a mid-run steer lands next turn and a post-terminal follow-up resumes the Thread, with the finish-during-steer race re-routing to `resume` carrying the original message and an explicit id never continuing a concurrent Job's Thread; and a prompt and steer carrying quotes / newlines / `$(…)` / a leading dash arrive byte-identical over the stdin transport with no subshell executing.
- `test_task_command.py` — `commands/task.md` documents the pinned seam argv (`--profile`, `--read-only`, `--bash-timeout-s`, text on stdin) plus the Bridge-level `--resume`/`--fresh` routing, invokes `chinamax:chinamax` inline as a background addressable agent, and lists `Agent` in `allowed-tools`.
