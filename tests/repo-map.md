# repo-map — tests/

The pytest suite. Every test drives the Runtime and the Job supervisor at their process/CLI seam against the hermetic fake provider — never with SDK-level mocks, never with a mocked process layer, and never against a real endpoint (ADR 0011).

- `fake_provider.py` — the test bed, not a test: `FakeProvider` (a `ThreadingHTTPServer` on an ephemeral port serving `POST /v1/messages` as SSE from a scripted turn list, recording every request's body and headers) plus the script builders `turn()` (with an optional `usage=` merged over the message_start usage, so a turn can script the cache counters), `text_block()`, `tool_use_block()`, `thinking_block()` (a `{type, thinking, signature}` reasoning block served on the full-block path — never the tool_use-only partial path), the turn-gate seam `gate(index)` (holds the worker between two turns — records the request, sets `reached`, blocks until the caller sets `release` — the window a steer test writes into), and the fault builders `status_fault()` (any status, body and headers, e.g. `Retry-After`), `hang_fault()` (stall mid-turn, optionally after a half-served block), `ping_fault()` (keepalives and SSE comments only), `eof_fault()` (clean close before `message_stop`), `stream_error_fault()` (an `error` event inside a 200) and `drop_fault()` (connection closed with no response).
- `conftest.py` — shared fixtures and scripts: the autouse `keyless_home` (temp `HOME`, synthetic `model-keys.env`, ambient `ANTHROPIC_*` removed), `start_fake_provider`, and `job_env` — a `JobEnv` factory that binds a Profile to the fake through the real overlay path and runs a Job via `main(["exec", ...])`, or via `run_exec` when a `LoopConfig` is injected. `JobEnv` also exposes `result()`, `observations()` (every tool_result from the durable Thread) and `tree()` (the workspace contents, walked without following symlinks). Also holds the shared `BASH_COMMAND`/`REPORT_PAYLOAD` constants, the script builders `bash_then_report_script()`/`tool_script()`/`bash_script()`, `tool_results()`, the `OMIT` spec sentinel, the `write_overlay`/`write_keys` helpers, and the supervision seams — `Sleeper` (records backoff instead of sleeping), `SteppingClock`, `identity` jitter, `loop_config()`, and `reporter_events()`/`events_named()` for reading the reporter's JSON lines back out of stderr. It also holds the dispatch seam: the `dispatch_env` factory and its `DispatchEnv` (a workspace whose state root is a temp `CLAUDE_PLUGIN_DATA`, with `bind()` for a second Profile, `dispatch()` running the real `task` verb, and a `reap()` teardown that waits out every worker it started and pid-start-time-guards any SIGKILL), plus the `wait_for()`/`wait_for_status()` polls. And the lifecycle seam: `build_record()` (publish a record directly, for the states a live worker will not hold still in — now also `model` for the pinned-model row/detail and resume tests, and `supervised_at`/`supervision_timeout_ms` for the Bridge-supervision reap tests), `write_artifacts()`/`job_artifacts()`/`job_leftovers()` (the six per-Job artifacts, a nested steer `consumed/`, and a name-prefix sweep that catches a seventh), `aged()` (an ISO timestamp N seconds in the past, so a 60 s grace costs nothing), `dead_pid()` and `assert_wire_shape()` (no consecutive same-role messages, every `tool_use` answered).
- `test_fake_provider.py` — the harness itself: a scripted text turn is valid SSE for a raw SDK client.
- `test_walking_skeleton.py` — the loop: bash then report_result, the tool_result returned to the provider, the tool-less-turn nudge (parametrized over three stop reasons), bearer auth with the exact advertised tool list, and report_result sharing a turn with a sibling tool_use; plus the context-cache telemetry and prefix guards — one `usage` event per completed turn with the provider counters (None-dropped, the message_delta accumulation proven by `output_tokens`), a retried attempt contributing no usage, the request prefix (`system`/`tools`/`messages`) only ever growing across turns, and the system template fronting the instructional body before the per-Job `{workspace}`/`{posture}` slots (workspace and posture affecting only the tail); plus the reasoning wire seam — a Profile's `request_extras` merged into the wire body (a `thinking` extra verbatim, an `extra_body` extra's bare keys merged into the root never an `extra_body` wrapper, and `{}` adding nothing) and a returned thinking block replayed verbatim on the next turn with the prefix stable and the `thinking` extra constant.
- `test_transcript.py` — the Thread: replaying the JSONL reconstructs the history, and the outgoing delta is on disk before the request that carries it.
- `test_spec.py` — job-spec validation fails fast (missing field, wrong type, unknown key, non-existent workspace, a bad `inactivity_timeout_s`/`ladder_attempts` override, and an empty or wrong-typed `model`) with no request reaching the provider, plus the optional `model` field carried when present and None when absent.
- `test_liveness.py` — the supervision layer: a mid-stream hang retried (bounded in elapsed time, so a watchdog that never breaks the read fails), ping keepalives failing to mask that hang, 429 and 5xx clearing within the ladder with the exact 5/10/20 backoff, the classification table parametrized row by row, `Retry-After` floored then clamped, ladder exhaustion (six requests, five sleeps, nonzero exit, provider body preserved), the nullable inactivity payload, a 401 failing fast, and transcript atomicity across the two decisive half-stream shapes.
- `test_no_caps.py` — 120 turns under a clock that jumps four and a half hours per read still complete, and `LoopConfig`'s field set matches an exact allowlist so no cap can be added under any name.
- `test_profiles.py` — the five shipped rows (including each row's exact `request_extras` and the shipped-row reserved-key guard at both levels), overlay merge and field-level partial merge, the `request_extras` overlay cases (wholesale replace, `{}` disables, non-object rejected, a reserved key rejected at the top level and inside `extra_body`, the client-policy `timeout` and credential `extra_headers` keys rejected, a new overlay row carrying extras), shell-quoted key resolution, and the missing-profile / unknown-profile / missing-key fail-fast paths.
- `test_tools.py` — the rich set end to end: a happy path per tool against a real temp workspace, apply_patch's all-or-nothing rejection, and a raising tool (undecodable file, invalid regex) becoming an observation the loop continues from.
- `test_confinement.py` — containment and the denylist: absolute / `..` / symlink escapes, an in-workspace symlink still usable, the sibling-prefix case that a `startswith` check would pass, a directory symlink not followed by grep/glob/list_dir, every denied command family (parametrized), and the quoted-argument false positives that must still run.
- `test_bash_timeout.py` — expiry is an observation carrying the output so far, the backgrounded descendant dies with its process group while the Runtime survives, and every invalid `bash_timeout_s` (parametrized) fails spec validation while omission resolves to 600 s.
- `test_readonly.py` — the read-only posture: write tools absent from the advertised schema, a filtered-out or unregistered tool refused at dispatch, write-shaped bash blocked, and reads (including `2>&1` and `2>/dev/null`) unaffected.
- `test_dispatch.py` — detached dispatch: the id returned in under a second, the worker surviving a SIGKILL of its dispatching shell's whole process group, state readable from a fresh process afterwards, a genuinely failing spawn (a non-executable interpreter, no mocked process layer) marking the Job `failed`, the pid-write CAS losing its race harmlessly, a second claimant and a pre-claim cancel both exiting without running, `--bash-timeout-s` actually cutting a command short, a pinned `--model` reaching both the record and the wire (bracket-glob byte fidelity) while an unpinned dispatch uses the Profile default and an empty `--model` is refused with no record, a provider-rejected pinned model failing after exactly one attempt (PERMANENT, the pin still on the request), runtime/03's failure payload rendering onto `errorMessage` with the full JSON in the log, and a raising reporter never failing the Job.
- `test_status.py` — `status`: phase and progress preview while running then completed and listed exactly once, `--wait` returning within ~2 poll intervals of completion, `--wait` waking on new LOG lines with status and phase held still, every non-terminal return exiting 2 (progress wake-up and expiry alike) against 0 only when terminal, `--timeout-ms` clamping, the bridge-first row leading with the Bridge name (or `-` for a direct dispatch) via the shared `render_job_row`, `status --wait` stamping the Bridge-supervision heartbeat (the clamped bound, `touch=False` so `updatedAt` is untouched, `max`-only so a smaller later bound never lowers it, and nothing stamped on `--timeout-ms 0` or a terminal Job), a pinned model shown as `profile (model)` in the row plus a `model:` detail line on `status <id>` (shown once in a bare listing, escaped in both surfaces when it carries a control character), and a named-but-missing Job exiting 1 against an empty store.

- `test_state.py` — the durable store: the index rebuilt from record FILENAMES with a `<id>.result.json` beside a record still rebuilding to one Job, a subdirectory dispatch resolving to the repo's single state dir, state-root resolution with empty and relative values counting as unset, 0700/0600 across every artifact, `/proc/<pid>/stat` field 22 parsed past a comm carrying spaces and parentheses, `schemaVersion` present and unknown/missing fields tolerated, `bridgeName` round-tripping via `--bridge-name` and `sessionId` populated from `CHINAMAX_SESSION_ID` (absent → None), the session reaper now EXISTING (`reap_session`/`reap_orphans` + `reap --session`/`--orphans`, with only `reap` taking a session id — the inverse of the old no-reaper invariant, ADR 0004 reversed), and `resolve_job` refusing a miss or an ambiguous prefix.
- `test_concurrency.py` — two simultaneous dispatches (on two Profiles) both complete, `state.json` parses AND carries both ids, and each record keeps its own title, profile, pid, log and transcript.
- `test_result.py` — `result`: a completed Job's stored `response` rendered bare under the header line and `--json` emitting the stored artifact's bytes, an active Job exiting 2 with guidance to status against an unknown id exiting 1, and a payload-less terminal Job (failed, and derived-interrupted with its pointer to resume) still exiting 0.
