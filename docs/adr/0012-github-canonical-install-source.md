# GitHub is the canonical install source; rpi4 is a backup mirror

**Decided 2026-07-27.** The repo is published publicly at [github.com/kguo93/chinamax_plugin](https://github.com/kguo93/chinamax_plugin) under GPL-2.0, with `master` as the branch everywhere — GitHub's auto-created `main` is deleted. The Claude Code marketplace `chinamax-plugin` is re-added from GitHub, so a plugin install sources from GitHub rather than a local path (plugin v0.1.2). The rpi4 remote (`klg2138@rpi4:/home/klg2138/chinamax_plugin`) stays a pure git backup mirror: the remotes are `origin` = rpi4 and `github` = GitHub, and the operator pushes both interactively (the passphrase-locked key `id_ed25519_20251111_021203`, registered for github.com via `~/.ssh/config`). On the dev machine the conda env's `chinamax` package remains an editable install of the dev checkout — the GitHub-sourced install cache supplies commands, agents, hooks, and shims only; a fresh machine pins fully through setup's `CLAUDE_PLUGIN_ROOT` fallback.

Rejected: renaming `origin` to GitHub (rewrites the backup mirror's identity and every push already in muscle memory); one `origin` carrying dual push URLs (a single `git push` reaches both, but a GitHub auth failure or outage then blocks the backup push too, and the two remotes stop being independently addressable); adopting `main` (a rename owed to GitHub's default alone, against a `master` history and every existing clone); pinning the Runtime to the install cache (dev edits would stop taking effect until a reinstall); and reinstalling at 0.1.1 (an identical version reuses the stale cache directory, so the GitHub source would never actually land).
