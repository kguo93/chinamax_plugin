# Final results are the worker's self-report, envelope stripped, prose untouched

**Amended 2026-08-06.** Result fidelity is identical across Hosts; only the
adapter transport and native message-tool relay differ.

A Job's structured result is exactly the worker's mandatory `report_result` tool call ({outcome, summary, changed_files, commands_run, tests, failures, concerns}), Codex-style. We rejected a runtime audit layer (git-derived changed files, command-log cross-checks) to keep the runtime lean; the known cost is that worker models can under-report what they touched.

**Amended 2026-07-24**: the Bridge no longer relays the report verbatim. It strips the report scaffolding — status headers, the `report_result` envelope, "task completed" boilerplate — and fixes layout, so the final response reads as a clean answer rather than a raw worker dump. The worker's own sentences stay untouched: the Bridge may not omit, summarize, verify, judge, or add content of its own. Rejected: free summarization (haiku would drop detail on long Jobs) and full-rewrite-as-own-prose (weakens the fidelity guarantee this ADR exists for).

**Amended 2026-07-27**: the structured envelope is gone. `report_result` takes a single required `response` field — the worker's complete final answer, verbatim — and nothing else. The metadata fields ({outcome, summary, changed_files, commands_run, tests, failures, concerns}) were dropped because they pushed workers to compress the answer into a summary and pad it with lists nobody consumed: the full answer was never captured, so no relay could deliver it. `result` now renders the response bare under its one `<id>  <status>` header line, and the Bridge strips that header and relays the response untouched — the operator reads exactly what the worker wrote. Rejected: keeping optional metadata fields beside `response` (any second field invites splitting the answer) and reconstructing the answer Bridge-side from the transcript (the report must stay the worker's own final word).
