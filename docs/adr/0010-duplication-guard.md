# Duplication guard: contract language + Stop notice, no hard blocks

**Amended 2026-08-06.** The canonical Bridge contract now lives in
`skills/chinamax-bridge/SKILL.md`; Claude loads it and Codex adds a Host-aware
pre-tool backstop that blocks mutating setup/Agent calls outside yolo.

Claude is kept from redoing an in-flight Job's work by (1) the Bridge contract forbidding the Bridge from working itself, (2) a result-handling rule forbidding Claude-side substitute implementations when a Job fails or runs long, and (3) a non-blocking Stop-hook notice listing running Jobs. We rejected a PreToolUse hook hard-blocking Claude's own edits during write-capable Jobs: it would block legitimate parallel work on unrelated files and can misfire.

**Amended 2026-07-24**: the Bridge contract additionally forbids the Bridge from spawning any subagent — one named Bridge per dispatch, nothing beneath it (live transcripts showed a wrapper teammate re-spawning the Bridge unnamed). The result-handling rule tracks ADR 0007's amendment: envelope stripped, worker prose relayed untouched, never re-done or judged.

**Amended 2026-07-30**: the guard gains two injection legs and sheds the visible command surface. (1) A PreToolUse hook, filtered in-script on `agent_type == chinamax:chinamax`, injects a compact classification contract (classify → one seam verb → wait for terminal → exactly one verbatim relay; silent otherwise) as subagent-scoped additionalContext on every Bridge seam call — the closest realizable form of per-message injection, since no hook event fires when a teammate receives a SendMessage. (2) A UserPromptSubmit hook injects the live-Bridge roster plus the explicit-addressing routing rule into the main context: only messages that name a Bridge, its Profile, or the worker are forwarded; everything else is main's own work. The internal commands (steer, resume, cancel, result, logs) are deleted rather than guarded. Still no hard blocks — the hooks inject context, they never deny tool calls (rejected again: a Bash allowlist for the Bridge, where one false positive deadlocks a mid-Job Bridge).

**Amended 2026-08-17 (0.7.2): the injection filters key on the subagent TYPE `agent_type = chinamax:chinamax`, and the `SubagentStart` matcher is corrected to catch it.** The 2026-07-30 leg (1) is right that the PreToolUse filter keys on `agent_type == chinamax:chinamax` — Claude Code sets `agent_type` to the subagent TYPE (added to PreToolUse in CLI 2.1.218; `SubagentStart` itself added 2.1.214), NOT the teammate name. But the `hooks.json` / `codex-hooks.json` `SubagentStart` matcher was written against a stale name-based assumption as `chinamax_bridge|chinamax[-_]`, which never matches the colon-form type `chinamax:chinamax`, so the **spawn-time** contract injection silently never fired for a Claude Bridge. The matcher is broadened to `chinamax:chinamax|chinamax_bridge|chinamax[-_].*` and kept in parity across both hook files. The PreToolUse **reinforcement** leg was unaffected — `chinamax` is a substring of the type too, so the module's `"chinamax" in agent_type` test needs no change. The Codex Bridge's `agent_type` was not live-verified (mocked coverage; the broadened matcher is a strict superset, harmless there). Stale "agent_type is the teammate NAME" comments in `bridge_contract.py`, `hooks/CLAUDE.md`, and `src/chinamax/hooks/CLAUDE.md` were corrected. This change touches `hooks/hooks.json` (governed by ADR 0004) only in its bridge_contract registration matcher; the session-ownership semantics ADR 0004 owns are unchanged.

**Amended 2026-08-18 (0.7.4, Codex-specific):** Live Codex 0.147.0 probing confirmed that `SubagentStart` provides the complete canonical contract at Bridge spawn, but inter-agent `followup_task`/`send_message` delivery does not provide a usable recipient-side `UserPromptSubmit` payload. The parent-side PreToolUse payload contains an encrypted message, so rewriting it cannot preserve the inbound text. The generated `chinamax_bridge.toml` therefore derives its persistent `developer_instructions` from the exact `skills/chinamax-bridge/SKILL.md` bytes. That developer layer binds every Bridge model request, including later messages and context restored after compaction, without a maintained Codex contract copy. Existing Codex `SubagentStart` injection and `PreToolUse(Bash)` reinforcement remain; the initial duplicate is intentional, and each Bridge Bash still receives the existing extra hook context. No global `UserPromptSubmit` contract hook was added. Claude's `PreToolUse(Bash)`, hook files, and all Claude Bridge behavior remain unchanged.
