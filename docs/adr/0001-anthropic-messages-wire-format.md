# Runtime speaks Anthropic Messages, not OpenAI chat-completions

The original brief asked for a runtime speaking each provider's OpenAI-compatible chat-completions endpoint. We chose the providers' Anthropic-compatible Messages endpoints instead (`api.deepseek.com/anthropic`, `api.xiaomimimo.com/anthropic`, `api.z.ai/api/anthropic`, `api.minimax.io/anthropic`, `api.moonshot.ai/anthropic`): these exact base URLs, model strings (e.g. `deepseek-v4-pro[1m]`), and keys are already proven in daily use by the implement-handoff skill, whereas each provider's chat-completions path, model IDs, and tool-calling quirks were unverified. Provider genericity is preserved — any Anthropic-compatible endpoint works as a Profile — and the official `anthropic` Python SDK replaces hand-rolled wire code.
