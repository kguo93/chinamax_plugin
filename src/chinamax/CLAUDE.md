# src/chinamax/ — conventions

Inventory lives in `./repo-map.md`. Domain vocabulary lives in `../../CONTEXT.md`.

## Gotchas

- **Never hardcode `/home/...`.** Every `~/.claude/...` path goes through `Path.home()` (`profiles.overlay_path()`, `profiles.keys_path()`). The suite runs keylessly by pointing `HOME` at a temp dir; a hardcoded path reads the operator's real keys.
- **Key parsing is shell-quoted.** `model-keys.env` is normally consumed by bash-sourcing it and single-quotes some values, so `load_keys()` unquotes with `shlex`. A bare `split("=", 1)` hands the provider a token wrapped in literal `'` and every live dispatch fails auth while the hermetic suite stays green.
- **Bearer auth only.** Build clients through `provider.build_client()` — `auth_token=`, never `api_key=`. `run_exec()` pops `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_BASE_URL` before any client exists; put that sanitization in the shared entry, not in a verb handler, because later slices call `run_exec` in-process.
- **`max_retries=0` is deliberate, and `liveness` is the only retry layer.** The SDK retries 408/409/429/5xx twice by default, which turns six ladder attempts into eighteen unlogged requests — `test_ladder_exhaustion_fails_job` fails with `assert 18 == 6` the moment it is removed. Never add an ad-hoc retry anywhere else.
- **Termination keys on the absence of `tool_use`, never on `stop_reason`.** `end_turn`, `max_tokens` and `stop_sequence` all produce a tool-less turn; an implementation keyed on `end_turn` loops forever on the other two. `report_result` is the only terminal path — there are no wall-clock or turn caps anywhere (ADR 0002).
- **A tool_use must never raise.** Unknown tool names and schema violations come back as error `tool_result` blocks, so no model-chosen name can kill a Job. `validate_input` deliberately accepts undeclared fields: the schemas do not set `additionalProperties: false`, and rejecting extras would let an embellished `report_result` payload block the only way to finish.
- **The result is verbatim** (ADR 0007): no normalization, no field synthesis, no audit. "Verbatim" is semantic JSON equality, not byte equality — the SDK reparses `input_json_delta`, so the file is written `sort_keys=True` and compared parsed.
- **The transcript is write-ahead.** Append and flush the outgoing delta BEFORE the API call, the assembled assistant turn after. Later slices depend on this ordering; batching the writes silently breaks them. Records carry `{v, ts, kind}`; only `kind: "message"` replays.
- **bash drains both pipes concurrently.** Reading one to EOF first deadlocks once the other fills its OS buffer — which is exactly the runaway case the bounded tail buffers exist for. The readers are joined only AFTER a timeout has killed the process group: a backgrounded descendant inherits the pipes, so EOF arrives only once the whole group is gone.
- **Never inject per-request-varying bytes into `system`, `tools`, or any already-sent message.** Provider context caching (ADR 0001) is exact-prefix-matched: a timestamp or job id formatted into the system prompt, a reordered tool list, or an edit to sent history silently forfeits the ~10x cache-hit discount on every later turn. The variable `{workspace}`/`{posture}` slots live in the system prompt's TAIL for this reason. The regression shows up in the per-turn `usage` events — `cache_read_input_tokens` collapsing to ~0 from turn 2 on. Those events reach the Job log through the REPORTER; the worker's bare stderr lands in the spawn log, which `logs` hides whenever the progress log is non-empty.
- **`request_extras` merges LAST and is constant per Job** (ADR 0006). `stream_with_ladder` unpacks `profile.request_extras` after the five Runtime-built request keys, so it can only add keys, never reorder the prefix — constant by convention, not by deep-freeze (the frozen dataclass does not freeze the dict; nothing mutates it, the merge only unpacks it). The SDK merges an `extra_body` value into the JSON body ROOT, so on the wire you assert the BARE key (e.g. `"reasoning_effort"`), never an `"extra_body"` wrapper. Thinking blocks the provider returns are ordinary Thread history — `_block_to_dict` keeps them, they replay verbatim on every later turn and across resume, and they are NEVER stripped or filtered (live-verified all five providers 2026-08-01).

## Host boundaries (2026-08-06)

- `host.py` is the only Host-resolution seam. Resolve and bind `HostContext` at
  CLI/hook boundaries before accessing Profiles, keys, or state.
- Claude paths (`~/.claude`, `CLAUDE_PLUGIN_*`, `chinamax`) and Codex paths
  (`~/.codex`, `PLUGIN_*`, `chinamax-codex`) are intentionally disjoint.
- `state.JobStore` records `host`; Codex rejects hostless/foreign records while
  Claude normalizes hostless legacy records as Claude.
- `doctor.codex_setup_plan()` is a genuinely non-mutating, redacted preview;
  `apply_codex_setup()` is the explicit consent-digest transaction. Keep Codex
  config edits TOML-preserving via `tomlkit`, use Host-owned key/overlay paths,
  and never place credential bytes in a preview or digest.
- Codex SessionEnd ownership is `sessionId` plus `sessionToken`; resumes must
  copy both so a detached reaper cannot touch a newer same-id Host Session.
- Keep Codex-specific naming/permission logic in `codex.py` or adapters. The
  Runtime's `--read-only` remains independent of Codex's sandbox/yolo mode.

- **No wall-clock bound and no turn cap, under any name.** `LoopConfig` is the whole configuration surface and `test_no_caps.py` asserts its field set against an exact allowlist, so a `max_duration` or `loop_limit` fails the suite rather than slipping past a name-pattern check. The 120-turn simulated-long-clock run is the real proof — a cap hidden as a module constant would slip past the allowlist.
- **The watchdog resets ONLY on content-bearing events**, never on `ping`, SSE comments, or raw bytes. A `ping` keepalive is an ordinary parsed event on this wire format, so resetting on "any traffic" lets a healthy proxy mask a stalled model — the exact hang the watchdog exists to catch. The SDK happens to drop pings before they reach us; `CONTENT_BEARING_EVENTS` states the rule regardless, because a byte-level read timeout (which httpx's `read` is) demonstrably cannot do this job.
- **`response.close()` alone does NOT unblock a parked read** — closing the fd leaves the loop thread stuck in `recv`. `InactivityWatchdog._close` reaches `response.extensions["network_stream"].get_extra_info("socket")` and calls `shutdown(SHUT_RDWR)` first; that is what breaks it. Removing the shutdown leaves every test green and every real hang eternal, which is why `test_midstream_hang_retried` asserts an elapsed-time bound as well as a retry count.
- **The watchdog reads a real monotonic clock, never `config.clock`.** The injected clock governs backoff and turn timestamps only; shrinking the inactivity bound in a test must work without advancing it.
- **Armed per attempt, disarmed and joined in a `finally`.** A stale timer must never be able to close a later attempt's stream. Its own close error is caught inside `run_attempt` and classified transient — it never escapes into `loop.py`.
- **An attempt is all-or-nothing at `message_stop`.** Nothing — tool_use blocks, `report_result` capture, transcript append — reaches `loop.py` before then, so an aborted attempt cannot half-apply a turn. A clean EOF *before* `message_stop` is an interrupted attempt, classified transient, never a completed turn.
- **Retries replay the in-memory snapshot, never a re-parse of the transcript**, so a torn JSONL line cannot fail a Job for the wrong reason. The canonical history is appended only when an attempt completes; retries land as `kind: "retry"` records that never replay.
- **Classification is an explicit table with a permanent DEFAULT.** A post-HTTP-200 `error` event is classified by its own error `type`, not by the enclosing 200. Mid-stream failures arrive as RAW `httpx` exceptions — the SDK only wraps errors raised during the request phase — so `classify` must keep matching `httpx.HTTPError` as well as the `anthropic` types.
- **Attempts 1..N means exactly N-1 sleeps** — never one after the final attempt. `Retry-After` is a floor on the post-jitter sleep and is then clamped to the cap; only delta-seconds parse, and an HTTP-date is ignored with a warning rather than guessed at. Jitter is injected so test expectations never couple to a PRNG sequence.
- **The failure seam is `run_exec`, not the loop.** The Runtime owns no state store, so ladder exhaustion and a permanent classification end the run there — exit 1 plus one `emit_event("failure", …)` line whose `status_code`/`provider_body` are nullable because inactivity and connection failures have no HTTP response. The jobs scope consumes that payload; do not reshape it here.

## Durable Job store (ADR 0003, ADR 0004)

- **`flock` goes on the `state.lock` sidecar, never on `state.json`.** Every write publishes by tmp+rename, and renaming over a locked file leaves the holder locking an unlinked inode — mutual exclusion silently voids itself while every test stays green.
- **`JobStore.update()` is the ONLY mutation path.** It takes the lock, re-reads, applies the change only if `expect` still holds, then tmp+renames. Compare-and-swap rather than last-writer-wins is what stops a late heartbeat resurrecting `running` over a terminal write and what makes jobs/02's cancel un-outrunnable. Never add an ad-hoc record write.
- **The index rebuild is a WRITE and holds the same lock.** `job_ids()` double-checks: compare outside, re-compare and rebuild inside. An unlocked rebuild racing a mutator's record-then-index pair puts a stale index over a fresh one. Mutation order is always record-then-index.
- **The record scan is `_RECORD_RE`, never `jobs/*.json`.** The bare glob swallows `<id>.result.json` and registers phantom Jobs. `_write_file`'s temporaries are dot-prefixed for the same reason.
- **Records are the source of truth; `state.json` is a derived id cache** compared as an id SET derived from FILENAMES, never from record contents — the index exists so a read need not open every record. An empty or unparsable record (including one caught between the `O_EXCL` reservation and its first publish) is reported malformed, never dropped and never allowed to hide the healthy Jobs beside it.
- **An empty or relative `CLAUDE_PLUGIN_DATA`/`XDG_STATE_HOME` counts as UNSET.** A relative root resolves differently in the dispatcher and in the worker, which runs from a different cwd.
- **Dirs 0700, files 0600 — including the two the Runtime opens itself.** The worker precreates `transcript_path` and `result_path` because ordinary Python creation under the default umask yields 0644, and re-applies 0600 to `result_path` afterwards: the Runtime's tmp+rename replaces the inode with one carrying the temporary's mode.
- **`/proc/<pid>/stat` field 22 is parsed by splitting after the LAST `)`.** The comm field is parenthesized and may itself contain spaces and parentheses, so a naive whitespace split ships green through every test but `test_pid_start_time_parsed_with_parens_in_comm` and then feeds a wrong start-time into jobs/02's kill decision. Unreadable `/proc` yields `None`, never a failed dispatch.
- **Losing the post-`Popen` pid-write race is HARMLESS.** That CAS applies only while the record is still `queued`; a worker that already claimed or finished makes it fail, and the dispatcher logs and exits 0. Only failures BEFORE the child exists mark the Job `failed`. Marking a Job failed because bookkeeping lost a race strands a live worker under a terminal record.
- **The worker calls the Runtime IN-PROCESS through `execute_spec`,** the same validated entry `exec` uses, and builds its spec through `parse_spec` so a half-written record fails with a named field. It never subprocesses back into `exec` and never re-implements the loop.
- **The heartbeat is a daemon thread stopped AND JOINED before the terminal write,** so a beat in flight can never land after it. It exists for jobs/02's stale detector only — `status --wait` deliberately does not wake on `updatedAt`, or every Job would look busy every 30 s. `RECORD_THROTTLE_S` and `HEARTBEAT_INTERVAL_S` move together with that detector's 60 s grace.
- **`status --wait` watches the log's `(size, inode)`, not its line count.** That is O(1) per poll and is what keeps a long single phase from going silent for the whole window. The poll runs on a MONOTONIC clock and `--timeout-ms` clamps to `WAIT_TIMEOUT_MS` rather than turning a bounded poll into an unbounded block. The DEFAULT bound (`WAIT_TIMEOUT_DEFAULT_MS`, 240 s) is decoupled from that clamp CEILING (`WAIT_TIMEOUT_MS`, lifted to 900 s in relay-01) so the Bridge's `--timeout-ms 900000` long-poll is honored, not capped, while a direct `/chinamax:status --wait` still defaults to 240 s. `test_wait_timeout_is_clamped` monkeypatches `WAIT_TIMEOUT_MS`, so the clamp must keep keying on it.
- **The exit-code set {0, 2, 1} is TOTAL.** Every non-terminal return is 2 — including an early wake-up on progress. A progress wake-up exiting 0 tells the Bridge the Job finished mid-run.
- **`logs` surfaces the spawn log when the progress log is EMPTY, never when status is `failed`.** The crash it exists for — a worker dying on import — leaves the record `queued`, so a status-keyed condition hides the spawn log in exactly the case it was created for.
- **Jobs are session-scoped (ADR 0004, reversed 2026-07-30).** `sessionId` (populated from `CHINAMAX_SESSION_ID`, which `SESSION_ID_VARIABLE` now points at) IS the owning-session field: `reap_session` (SessionEnd → `cancelled`) and `reap_orphans` (SessionStart → `interrupted`) key Job lifecycle off it, sweeping every store via `iter_workspace_stores`. Session liveness is a `<data root>/sessions/` registry read with the `worker_gone` family (`session_alive`), NOT `os.kill(pid, 0)`; the owning Claude pid is recovered by `resolve_owner_process`'s `/proc` ancestor walk. Reaps reuse `terminate_tree` (never a second kill path) with the short `SESSION_REAP_GRACE_S`/`SESSION_REAP_CONFIRM_S`.

## Lifecycle verbs (result / cancel / resume / stale / prune)

- **Selection and liveness live in ONE place — `state.py`.** `resolve_selector` is the single resolver (`resolve_job` is a thin wrapper), `effective_status`/`is_active`/`latest_key` the single grading, and no verb re-derives any of it. A parallel helper is how `result` and `status` start disagreeing about what "the latest Job" means.
- **`effective_status` grades `queued` as well as `running`.** The dispatcher writes the child pid immediately after `Popen`, so a worker that died before claiming leaves a `queued` record with a dead pid — grading only `running` strands that Job active forever.
- **"Provably gone" is ESRCH ONLY, plus zombie, plus a `pidStartTime` mismatch.** A `PermissionError` (EPERM) means the process EXISTS and must read as ALIVE. A zombie still answers signal 0, so `/proc` state `Z` has to count as gone or a crashed worker reads alive forever. Every degradation resolves toward alive: no usable pid is never probed and never signalled (`os.kill(0, 0)` would hit the caller's own group, and 1 is init), a missing `pidStartTime` falls back to the ESRCH test alone, and only a `/proc` read failing AFTER signal 0 succeeded counts as gone (the process died mid-check).
- **`worker_gone` is exposed separately from `effective_status` on purpose.** jobs/03's relaunch reclaim needs the liveness half WITHOUT the 60 s grace: an explicit relaunch verifies liveness directly rather than guarding against a delayed heartbeat.
- **Stale detection is READ-SIDE; `reap_orphans` is the ONE writer of stored `interrupted`.** A crash still derives `interrupted` read-side (stored status stays `running`/`queued`, Thread resumable). Only a dead-session reap WRITES `interrupted` — a policy-dead, terminal, prunable record. `_resume_source` refuses a STORED-`interrupted` source (a DERIVED one stays resumable), and `STATUS_INTERRUPTED` is in `TERMINAL_STATUSES`/`FINISHED_STATUSES` but prune grades the STORED status so a DERIVED-interrupted crash is never pruned. `STALE_GRACE_S` is twice `HEARTBEAT_INTERVAL_S`; the two move together or a live-but-quiet worker gets reported dead.
- **An interrupted Job returns 0 from `status --wait`, immediately.** It will never leave that state on its own, so a poll-relay told 2 would poll a dead worker for the life of the Bridge. The completed-versus-interrupted distinction lives in the OUTPUT, never in a fourth exit code.
- **CANCEL KILLS THE TREE, AND THE GROUP IS NOT THE TREE.** The bash tool starts every command in its OWN session, so one `killpg` on the worker's group leaves those children running. `terminate_tree` snapshots descendants FIRST (an orphan reparents to init the instant its parent dies), SIGTERMs every distinct group in the set, waits the grace, RE-SCANS from the survivors for children born after the snapshot, then SIGKILLs. A pid whose start time no longer matches is skipped, never signalled. If anything targeted survives, cancel REPORTS the pids and exits non-zero rather than writing `cancelled` over a Job it did not stop.
- **Cancel's status write is the same locked CAS, expecting a non-terminal record.** A worker that completed during the kill keeps its result; cancel then reports the terminal status instead. A not-yet-started Job is marked cancelled directly, which is safe only because the worker's claim is that same CAS — the two compete for one lock and the loser exits.
- **Resume does everything inside ONE critical section.** Guard, source resolution, transcript copy and record creation share the lock: copying after it would let a concurrent prune drop the source in between, and two concurrent resumes could both see "nothing active". The DISPATCHER writes the copy — a worker only ever reads its own transcript. `create_resume` therefore uses the lock-free internals (`_load_locked`, `_publish`, `_sync_index`); calling `job_ids()`/`update()` from inside would deadlock, since `flock` on a second descriptor in the same process blocks rather than nesting.
- **Normalization REPAIRS, never truncates.** A torn trailing line is dropped; an assistant turn with unanswered `tool_use` blocks is KEPT and answered synthetically — a normally completed Job ALWAYS ends that way, because the loop terminates on the `report_result` tool_use without answering it, so dropping the turn would delete the terminal report from every resume; and a trailing user turn takes the follow-up as another text block rather than becoming two consecutive user messages.
- **A seeded history always ends in an UNSENT user turn.** The loop sends it without re-appending it to the transcript and never appends the spec's prompt as a second user message — appending both delivers the follow-up twice. `seed_transcript` also switches `Transcript` to append mode; without that the fresh-run truncation deletes the copy the dispatcher just wrote.
- **Pruning deletes SIX artifacts, not five** — `.json`, `.log`, `.spawn.log`, `.thread.jsonl`, `.result.json`, and the `.steer/` directory RECURSIVELY (jobs/03 nests `consumed/` inside it, which a flat unlink loop leaves behind). Record `.json` goes FIRST, so a concurrent reader either resolved the Job before the prune or cannot see it at all. Symlinks are never followed, missing files are tolerated. `_prune_locked` grades the STORED status: active Jobs and DERIVED-`interrupted` crashes (stored `running`/`queued`) are never pruned and never counted toward the 50 — pruning a resumable Thread destroys exactly the crash recovery it exists for — while a reaped STORED-`interrupted` record IS finished and prunable.
- **Pruning runs on dispatch and on terminal transitions only**, never on a throttled progress update or a steer write, which would scan-and-unlink constantly.

## Steer queue (jobs/03, ADR 0008)

- **The queue-file name is `<epoch-ms>-<seq>-<6 rand>.md`, unique by construction.** `epoch-ms` orders across processes, `seq` (per-process, `%04d`) orders a same-ms burst, the random suffix makes the name unique outright — so `write_steer` stays a plain atomic tmp+rename through `_write_file`. Do NOT reach for `os.link` (strands the tmp inode) or an in-place `O_CREAT|O_EXCL` (exposes a half-written file to a concurrent drain), and do NOT derive the name by re-listing the directory (it can reuse an id whose same-ms predecessor already moved to `consumed/`, and the drain's dedupe then silently swallows the NEW steer). `_write_file`'s temporary ends `.tmp`, so the drain's `*.md` glob skips it.
- **Drain order is transcript-FIRST, rename SECOND.** `_drain_steers` appends the steer to the Thread (flushed) and only THEN renames the file into `consumed/`. Renaming first loses the steer to a crash in the gap — it is then in neither the queue nor the transcript. `STEER_ABORT_VARIABLE`/`_steer_abort_point` reproduce that exact window for the test.
- **Exactly-once across restart rests on the seeding contract.** The drain skips any queue file whose id already appears in the Thread (read once at startup by `read_steer_ids` into an in-memory set, updated as it drains — never re-parsed each boundary). That skip is sound ONLY because `task-worker` seeds the in-memory history from the transcript (`seed_transcript` + the repairing reader): without it the id sits in the transcript, the drain skips it, and the provider sees the steer ZERO times instead of once.
- **The wire shape is one user turn, never two.** A drained steer rides as an additional text block on the outgoing user message already carrying that turn's tool_results (`_attach_steer`); on the first iteration that message is the original prompt. In the transcript the steer is its OWN `message` record (id/enqueue-ts as metadata fields), so `read_repaired_messages` runs `coalesce_user_turns` to fold consecutive user turns back into the single turn the provider saw — third-party endpoints do not reliably tolerate consecutive same-role messages. The marker is `STEER_MARKER` (`[steer] `), fixed and asserted on.
- **Drain at the top of EVERY iteration, including the first** (a steer written before the worker starts lands before the first API call), and **sweep at the terminal transition** — `_sweep_undelivered` logs any steer that lost the accept-versus-terminate race, changing no delivery semantics. The log excerpt strips Unicode line/paragraph separators too (`_steer_excerpt`), not just the C0/C1 range `escape_control` reaches.
- **`steer` leans entirely on `effective_status`; it never re-derives liveness.** It accepts `queued`/effectively-`running`, refuses the three terminal states AND effectively-`interrupted` (pointing to resume, the only path that continues an interrupted Thread — and resume does NOT carry pending steers forward). Message precedence is argv-then-stdin (reusing `_read_prompt`); empty/whitespace and a message beyond `STEER_MAX_BYTES` are refused writing NO file. After the file lands the record is RE-READ: a Job gone terminal meanwhile is reported NOT delivered, never a false success.
- **`JobStore.claim` is the reclaim CAS, and only `task-worker` startup calls it.** A `queued` record is claimed as before; a NON-terminal record whose worker is provably gone by `worker_gone` (no stale grace — an explicit relaunch verifies liveness directly) is RE-claimed with the new pid. A live claimant or a terminal record still yields None and exit-without-running. No verb path reaches it.
- **`loop.py` depends on `state.py` for the queue helpers** (`list_steer_files`, `make_dir`, `escape_control`, the constants) — the plan puts the queue read/write helpers in `state.py` and the drain hook in `loop.py`. `state.py` does not import `loop`, so there is no cycle.

## Command / hook / setup seam (surface/02)

- **`normalize_argv` runs before argparse, for the eight operator verbs ONLY.** A slash-command shim forwards a single quoted `"$ARGUMENTS"` element, so a blank one becomes no args, a lone raw string is `shlex.split`, and `resume`'s and `steer`'s free-text prompt/message is kept intact after a `--` terminator (peeling a leading `task-` selector) — the two `_PROMPT_VERBS`. `exec`/`task`/`task-worker` stay excluded — normalizing a single-element tail there would `shlex.split` a spec path with a space out from under `exec`. `steer` MOVED into the normalized set for relay-01's `/chinamax:steer` command; the Bridge's `steer <id>` (message on stdin) is a two-element tail that `_normalize_resume` maps to the same `[<id>]`, so the stdin transport is unchanged. `steer` also switched to `resume`'s CLI shape (a single `args` positional, `--workspace` first) so one variadic positional collects the id and the post-`--` message; the id is optional, resolving bare via the shared `_active_target` (cancel-style single-active).
- **`list_jobs_tolerant(workspace)` is THE shared tolerant enumeration seam** for the workspace-scoped hooks (SessionStart digest, Stop notice); it wraps `open_store(workspace).load_records()` and returns `(records, unparseable_count)`. A malformed record is skipped and counted (never hides the healthy ones); a missing/truncated `state.json` rebuilds from the record files. `iter_workspace_stores()` is the cross-workspace sibling the reaps and the user_prompt roster sweep with. `render_job_row()` is the ONE bridge-first row helper `status`, the `reap` digests and both session digests render through, and `elapsed()` the shared duration rendering it uses — so the renderings never diverge.
- **`profiles` prints the api-key env-var NAME and PRESENT/MISSING, never the VALUE, on any stream.** So does `doctor.py`'s report (human and `--json`) — `test_setup.py` asserts a seeded sentinel key value never appears.
- **The doctor grades imports under the RESOLVED ENV python, never its own interpreter.** `diagnose` calls `check_deps` only when `find_env_python` returns a path; an absent env reports every dep missing WITHOUT running a probe, so a bootstrap run (system-python rung, no env) reads the env ABSENT instead of grading itself. Probes are injectable for hermetic tests (ADR 0011). `ok` is env-present AND all three deps AND state-writable; key presence is reported but never fails `ok`. The env python is recorded at `<data root>/python-path` (state-root rule minus `/state`), atomically, re-recorded only when the stored path no longer resolves.
- **The doctor FIXES after it diagnoses (2026-07-27), and the fixers are injectable like the probes.** `run_setup` = diagnose → `fix_missing` → re-diagnose (skipped when only the key template was written) → report; the exit code reflects the POST-fix diagnosis, and the report (human and `--json`, which gains a `fixes` array) records each fix row in run order. Production fixers: `conda create -y -n chinamax python=3.12` and `<env python> -m pip install -e '<repo>[test]'` (the `[test]` extra is what satisfies all three DEPS), each bounded by `FIX_TIMEOUT_S` and reported ONCE with an output tail — never retried; an absent conda is advice ("install Miniconda"), and an unresolvable `source_repo_path()` refuses rather than guessing. A healthy machine's setup runs no fixer. Tests MUST inject `create_env`/`install_deps` whenever the diagnosed env is missing, or the production fixer runs a real `conda create` on the test machine.
- **The key-file scaffold is comments-only and `O_EXCL`.** `write_key_template` creates `~/.claude/model-keys.env` at 0600 only when absent — an existing file (the operator's real keys) is NEVER touched, by `O_EXCL` rather than exists-then-write. The template parses to zero keys (`load_keys` ignores `#` lines) and carries one commented `<api_key_env>=` line per RESOLVED Profile (shipped + overlay) plus the extension recipe for any Anthropic-compatible provider (overlay row + key line) — keep `key_template_text` and `profiles.load_profiles` in lockstep, and remember the test fixture `keyless_home` pre-seeds this file, so a scaffold test must unlink it first.

## Confinement (ADR 0005)

- **Containment is component-wise, never `str.startswith`.** `resolve_in_workspace` compares with `Path.is_relative_to` against the workspace realpath, because workspace `/tmp/ws` must reject `/tmp/ws-evil/f` — which a prefix check accepts. `test_sibling_prefix_rejected` exists solely to pin this.
- **The workspace realpath is resolved once per Job** and carried on `ToolContext`. Re-realpathing the root on every check would double the syscalls a directory walk makes for no gain.
- **The denylist matches at COMMAND POSITION through the shared `lex_command`, never with a regex over the raw line.** A word-boundary regex matches inside `grep -rn "git push" docs/` and `pytest -k test_shutdown` and blocks both; the lexer turns each quoted string into one non-command token. `denied_reason` and `write_shaped_reason` must keep consuming that single lexer — two parallel matchers over the same string is the classic divergence source.
- **The lexer sets `commenters = ""` deliberately.** shlex's default treats `#` mid-word as a comment and discards the rest of the line, which would hide the `rm` in `echo a#b; rm -rf x` from the denylist entirely.
- **Short-flag clusters are inspected as clusters.** `git clean -fd` and `-fdx` are as destructive as `-f`, and a `\b`-anchored `-f` pattern matches none of them.
- **The read-only write-shaped check judges the TARGET and known file writers.** `2>&1`, `>&2` and `>/dev/null` are ordinary reads; redirection onto a real file and commands such as `tee` and `touch` are writes.
- **Read-only enforcement is the filtered registry, not the schema.** `build_registry(write)` produces one object serving both the advertised tools and the dispatch table, so a `write_file` call replayed from a resumed Thread is refused at dispatch. Omitting a tool from the schema alone stops only a model that reads the schema.
- **Do not expand the denylist.** Network egress, process signalling and quoting/substitution evasions are out of scope by decision, as are the read-only bash bypasses (`python -c`, heredocs, `truncate`). ADR 0005 documents that residual risk rather than defending it; chasing it is how a tool-layer policy grows into a bad sandbox.
- **A bad `bash_timeout_s` fails spec validation, never at command time** — it would otherwise kill every command the Job runs. `bool` is rejected explicitly there too.
