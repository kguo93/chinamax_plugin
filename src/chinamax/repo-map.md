# repo-map — src/chinamax/

The Runtime — the agent loop that owns one Job's conversation with a provider — plus the Job supervisor that makes a dispatch durable and detached.

- `__init__.py` — package docstring, `ChinamaxError` (the operator-facing failure type, reported at the CLI seam) and `ToolError` (the model-facing tool refusal, rendered as an error observation).
- `__main__.py` — the CLI seam for every verb. `main(argv)` parses `exec`, `task`, `task-worker`, `status`, `logs`, `result`, `cancel`, `resume`, `steer`, and surface/02's `profiles` and `setup`, and maps failures onto the shared exit codes (0 terminal / 2 active / 1 usage-or-resolution). It first runs `normalize_argv` — collapsing the single quoted `"$ARGUMENTS"` element a slash-command shim forwards (blank → no args, a lone raw string → `shlex.split`, `resume`'s prompt kept intact after `--` via `_normalize_resume`) for the seven operator verbs only, leaving the internal verbs untouched. `run_profiles()` renders each Profile's endpoint/model and key PRESENT/MISSING (never a value); `setup` delegates to `doctor.run_setup()`. `execute_spec(spec, config, reporter, steer_dir)` is the shared entry — it sanitizes the ambient `ANTHROPIC_*` variables, resolves the Profile and key, builds the `LoopConfig`, opens the Thread (appending when the spec sets `seed_transcript`), runs the loop (draining `steer_dir` when the worker supplies one) and writes the result atomically; `run_exec(spec_path, config)` wraps it for `exec` and is the failure seam (a `RunFailure` becomes one structured reporter line plus exit 1). The supervisor verbs: `run_task()` (fail-fast prompt/workspace/Profile resolution, then the durable record and `_spawn_worker()`'s detached `Popen`), `run_task_worker()` (the compare-and-swap claim through `JobStore.claim` incl. jobs/03's crashed-worker reclaim, the in-process Runtime call through `execute_spec` with the Job's `steer_dir`, the heartbeat, and the terminal write), `run_status()` (the listing, one Job, and the bounded `--wait` poll), `run_logs()` (the progress log, falling back to the spawn log when it is empty), `run_result()` (the stored payload or the status-and-reason, plus `--json` from the stored artifact), `run_cancel()` (the process-tree sweep and the locked cancelled write), `run_resume()` (argv splitting, then the store's one-lock resume transaction and a detached spawn) and `run_steer()` (`effective_status`-gated enqueue with a post-write re-read, refusing terminal/interrupted Jobs to resume). Also `PREVIEW_LINES` (4), `RECENT_LIMIT` (20), `RESULT_FIELDS` (the payload's seven fields in schema order), `CANCEL_REASON`, `DEFAULT_RESUME_PROMPT`, `STEER_MAX_BYTES` (256 KB), and the `_read_prompt` (argv-or-stdin, reused by `steer`) / `_read_steer_message` / `_steer_refusal` helpers.
- `state.py` — the durable per-workspace Job store (ADR 0003/0004) and the shared selection and liveness predicates every verb reads. Layout and keying: `state_root()` (`CLAUDE_PLUGIN_DATA` then `XDG_STATE_HOME`, empty or relative counting as unset), `resolve_workspace_root()` (git-toplevel resolution), `workspace_key()`, `open_store()`. `JobStore` owns the paths (`state.json` index, `state.lock` sidecar, and the six per-Job artifacts `<id>.json`/`.log`/`.spawn.log`/`.thread.jsonl`/`.result.json`/`.steer/`), the `O_EXCL` `reserve_id()`, the single locked compare-and-swap `update()`, the `claim()` variant (jobs/03's queued-claim-OR-reclaim-a-crashed-worker CAS), the filename-derived index rebuild (`job_ids()`, `load_records()`), the `resolve_job()` selector, `enqueue_steer()`, `prune()` (newest `PRUNE_KEEP` finished Jobs, every artifact removed under the lock, the `.steer/` tree recursively) and `create_resume()` (guard, source resolution, transcript copy and record creation in ONE critical section). Plus the record schema (`SCHEMA_VERSION`, `RECORD_DEFAULTS`, `new_record()`, `normalize_record()`), the shared resolver `resolve_selector()`, the tolerant enumeration `list_jobs_tolerant()` (records + unparseable count, the seam both session hooks and `status` read), the selection and liveness set — `worker_gone()` (the provably-gone predicate, no grace), `effective_status()` (deriving `STATUS_INTERRUPTED`), `is_active()`, `latest_key()`, `elapsed()` (the shared duration rendering), `usable_pid()` — the `/proc` primitives (`parse_stat_fields`, `parse_pid_start_time`, `read_proc_stat`, `read_pid_start_time`, `ProcessInfo`, `read_process`, `process_table`, `descendants`) and `terminate_tree()` (snapshot → SIGTERM by group → grace → re-scan → SIGKILL → report survivors), the steer-queue helpers (`write_steer()`/`list_steer_files()`/`steer_enqueued_at()`/`steer_now_ms()`, `STEER_CLOCK_VARIABLE`, `STEER_CONSUMED_DIRNAME`), the timing constants (`RECORD_THROTTLE_S` 2 s, `HEARTBEAT_INTERVAL_S` 30 s, `STALE_GRACE_S` 60 s, `TERMINATE_GRACE_S` 10 s, `POLL_INTERVAL_S` 2 s, `WAIT_TIMEOUT_MS` 240 000, `PRUNE_KEEP` 50), the 0700/0600 helpers (`make_dir`, `precreate`, `secure_file`), the log readers (`log_signature`, `tail_lines`), `escape_control()`/`summarize()`/`render_failure()`, and the two progress mechanisms `ProgressReporter` and `Heartbeat`.
- `spec.py` — `JobSpec` and the job-spec parser/validator: the public dispatch contract (`workspace`, `profile`, `prompt`, `transcript_path`, `result_path`, optional `write`/`job_id`/`seed_transcript`/`bash_timeout_s` and the supervision overrides `inactivity_timeout_s`/`ladder_attempts`/`backoff_base_s`/`backoff_cap_s`), plus `DEFAULT_BASH_TIMEOUT_S` (600 s).
- `confinement.py` — the tool-layer policy (ADR 0005): `ToolContext` (workspace realpath, posture, bash timeout), `resolve_in_workspace()`/`contained()` (component-wise realpath containment), `lex_command()` → `Stage` (the one shlex-based command lexer), and the two predicates over it — `denied_reason()` (the operator's hard bans) and `write_shaped_reason()` (read-only Jobs).
- `profiles.py` — `Profile`, the shipped-plus-overlay resolution (`load_profiles`, `resolve_profile`, `format_available`) and API-key lookup from `~/.claude/model-keys.env` (`load_keys`, `resolve_key`).
- `doctor.py` — the `/chinamax:setup` environment doctor (surface/02): `diagnose()` (one-pass report — env python, deps under the RESOLVED env python, per-Profile key presence, state-dir writability) with injectable `find_env_python`/`check_deps` probes, `run_setup()` (the verb: human or `--json`, exit 0 iff `ok`), `render_report()`, the `<data root>/python-path` record (`data_root`, `python_path_file`, atomic re-record only when stale), `source_repo_path()` (editable-install origin, else `${CLAUDE_PLUGIN_ROOT}`), and the production probes.
- `provider.py` — `sanitize_environment()` and `build_client()`: the `anthropic` SDK client for one Profile (bearer auth, `max_retries=0`, and a structured `httpx.Timeout` whose read budget backstops the inactivity watchdog).
- `liveness.py` — the supervision layer (ADR 0002): `LoopConfig` + `build_config()` (the inactivity/ladder/backoff knobs and the injected clock, sleeper and jitter seams), `InactivityWatchdog`, `run_attempt()` (one streaming call, all-or-nothing at `message_stop`), `classify()` with the transient/permanent table, `parse_retry_after()`, `backoff_sleep()`, `stream_with_ladder()` (the ladder itself), `RunFailure` (the terminal failure payload) and `emit_event()` (the structured progress reporter).
- `loop.py` — `run_loop()`: the streaming Messages tool-use loop, the system prompt, the tool-less-turn nudge, and the report_result termination rules. Builds the Job's posture-filtered registry and its `ToolContext` once, then routes every tool_use through them; each turn goes through `liveness.stream_with_ladder`. `_seed_history()` rehydrates a pre-populated Thread when the spec sets `seed_transcript`, in which case the seeded trailing user turn is sent without being re-appended and the spec's prompt is never appended as a second user message. The steer drain (when the worker passes a `steer_dir`): `_drain_steers()` runs at the top of EVERY iteration — reading `list_steer_files` in name order, folding each new steer's `STEER_MARKER`-prefixed text onto the outgoing user turn (`_attach_steer`), appending it to the Thread (transcript FIRST) and only THEN renaming into `consumed/` (`_consume_steer`), skipping any id already in the startup-seeded dedupe set — with the flush→rename crash window a test can hit via `_steer_abort_point`/`STEER_ABORT_VARIABLE`; `_sweep_undelivered()` logs any steer still queued at the terminal transition; `_steer_excerpt()` control-cleans a steer for its one log line. Also the closed progress vocabulary `PHASES` (`PHASE_STARTING`, `PHASE_CALLING_MODEL`, `PHASE_RUNNING_TOOL`, `PHASE_REPORTING`) and the optional `reporter` seam the supervisor mirrors into a Job's log and record.
- `transcript.py` — the Thread, over the versioned `{v, ts, kind}` record schema: `Transcript` (write-ahead JSONL writer, with `append_message()`, `append_steer()` (a replayable user turn carrying the steer id/enqueue-ts as metadata fields), the non-replayable `append_retry()`, and an `append` mode for a seeded run), `read_messages()` (the replay reader), `read_steer_ids()` (the drain's dedupe seed), the `STEER_MARKER` prefix, and the resume normalization — `read_repaired_messages()`, `repair_messages()` (a synthetic `tool_result` per unanswered `tool_use`, using `REPORTED_RESULT` for a terminal `report_result` and `INTERRUPTED_RESULT` otherwise), `coalesce_user_turns()` (folds a steer's own user record back into the turn the provider saw), `merge_follow_up()` (the follow-up joins a trailing user turn rather than doubling the role) and `write_messages()` (the dispatcher's copy).
- `hooks/` — the SessionStart + Stop session-lifecycle entrypoints (surface/02), reading state through the shared `state.list_jobs_tolerant`. See `hooks/repo-map.md`.
- `tools/` — the tool registry advertised to the provider. See `tools/repo-map.md`.
- `data/profiles.json` — the five shipped pro Profile rows (deepseek, mimo, glm, minimax, kimi), each `{name, base_url, model, api_key_env}`; `max_tokens` is an optional per-row override of the code default.
