# repo-map — src/chinamax/

Portability note (0.4.3): `host.py` selects native Linux/XDG,
macOS/Application Support, or Windows/Local AppData roots. `state.py` keeps the
Linux `/proc`/`fcntl`/POSIX path, uses psutil inspection with POSIX signals on
macOS, and uses psutil tree termination plus filelock sidecars and guarded ACL
mode operations on Windows. `_set_mode()` centralizes POSIX mode application,
while `atomic_replace()` centralizes temporary-file publication and bounded
Windows sharing-violation retries. `doctor.py` reports
conditional dependencies and new-platform Bash/Git/cygpath prerequisites.

The Host-neutral Runtime — the agent loop that owns one Job's conversation with a provider — plus the Job supervisor that makes a dispatch durable and detached. `host.py` resolves Claude/Codex boundaries and `codex.py` contains native adapter invariants.

- `host.py` — Host enum/context, explicit/env/plugin-evidence resolution, and isolated Claude/Codex roots.
- `codex.py` — deterministic Codex Bridge naming, Terra/low/no-fork spawn settings, and yolo permission guard.

- `__init__.py` — package docstring, `ChinamaxError` (the operator-facing failure type, reported at the CLI seam) and `ToolError` (the model-facing tool refusal, rendered as an error observation).
- `__main__.py` — the CLI seam for every verb. `main(argv)` parses `exec`, `task` (now with `--bridge-name`, `--model`), `task-worker`, `status`, `logs`, `result`, `cancel`, `resume`, `steer`, `reap` (`--session <id>` → cancelled / `--orphans` → interrupted, the internal seam the session hooks call), and `profiles` and `setup`, and maps failures onto the shared exit codes (0 terminal / 2 active / 1 usage-or-resolution). It first runs `normalize_argv` — collapsing the single quoted `"$ARGUMENTS"` element a slash-command shim forwards (blank → no args, a lone raw string → `shlex.split`, `resume`'s and `steer`'s prompt/message kept intact after `--` via `_normalize_resume`, the two `_PROMPT_VERBS`) for the eight operator verbs only, leaving the internal verbs untouched. `run_profiles()` renders each Profile's endpoint/model, key PRESENT/MISSING (never a value), and the resolved `request_extras` as compact JSON when non-empty; `setup` delegates to `doctor.run_setup()`. `execute_spec(spec, config, reporter, steer_dir)` is the shared entry — it sanitizes the ambient `ANTHROPIC_*` variables, resolves the Profile and key, builds the `LoopConfig`, opens the Thread (appending when the spec sets `seed_transcript`), runs the loop (draining `steer_dir` when the worker supplies one) and writes the result atomically; `run_exec(spec_path, config)` wraps it for `exec` and is the failure seam (a `RunFailure` becomes one structured reporter line plus exit 1). The supervisor verbs: `run_task()` (fail-fast prompt/workspace/Profile resolution, then the durable record and `_spawn_worker()`'s detached `Popen`), `run_task_worker()` (the compare-and-swap claim through `JobStore.claim` incl. jobs/03's crashed-worker reclaim, the in-process Runtime call through `execute_spec` with the Job's `steer_dir`, the heartbeat, and the terminal write), `run_status()` (the listing, one Job, and the bounded `--wait` poll — which stamps the Bridge-supervision heartbeat via `state.stamp_supervision` at entry on an active Job, off the clamped bound actually used), `run_logs()` (the progress log, falling back to the spawn log when it is empty), `run_result()` (the stored payload or the status-and-reason, plus `--json` from the stored artifact), `run_cancel()` (the process-tree sweep and the locked cancelled write), `run_resume()` (argv splitting, then the store's one-lock resume transaction and a detached spawn), `run_steer()` (id-optional `_split_resume_args`, then the shared `_active_target` resolution — bare targets the single active Job and several are listed, mirroring `cancel` — then an `effective_status`-gated enqueue with a post-write re-read, refusing terminal/interrupted Jobs to resume) and `run_reap()` (delegates to `state.reap_session`/`reap_orphans`, prints one bridge-first `render_job_row` line per reaped Job, survivors/ownerless-live to stderr). `_print_job` and the digests render through `state.render_job_row` (bridge-first). Also `PREVIEW_LINES` (4), `RECENT_LIMIT` (20), `CANCEL_REASON`, `DEFAULT_RESUME_PROMPT`, `STEER_MAX_BYTES` (256 KB), the shared `_active_target` id-optional resolver (`cancel` + `steer`), and the `_read_prompt` (argv-or-stdin, reused by `steer`) / `_read_steer_message` / `_steer_refusal` (distinguishing a reaped STORED-interrupted Job, and a dead-session reap from a `bridge terminated` one via the record's `errorMessage`) helpers; `_print_result`'s reaped hint draws the same distinction.
- `state.py` — the durable per-workspace Job store (ADR 0003/0004) and the shared selection and liveness predicates every verb reads. Layout and keying: `state_root()` (`CLAUDE_PLUGIN_DATA` then `XDG_STATE_HOME`, empty or relative counting as unset), `resolve_workspace_root()` (git-toplevel resolution), `workspace_key()`, `open_store()`. `JobStore` owns the paths (`state.json` index, `state.lock` sidecar, and the six per-Job artifacts `<id>.json`/`.log`/`.spawn.log`/`.thread.jsonl`/`.result.json`/`.steer/`), the `O_EXCL` `reserve_id()`, the single locked compare-and-swap `update()`, the `claim()` variant (jobs/03's queued-claim-OR-reclaim-a-crashed-worker CAS), the filename-derived index rebuild (`job_ids()`, `load_records()`), the `resolve_job()` selector, `enqueue_steer()`, `prune()` (newest `PRUNE_KEEP` finished Jobs, every artifact removed under the lock, the `.steer/` tree recursively) and `create_resume()` (source resolution refusing a reaped STORED-`interrupted` source, the lineage-scoped guard for an explicit selector — refusing only when the source's `lineageRoot` still has an active Job — else the workspace-wide bare guard, `bridgeName`/`lineageRoot`/`resumedFrom` inheritance, transcript copy and record creation in ONE critical section). Plus the record schema (`SCHEMA_VERSION`, `RECORD_DEFAULTS`, `new_record()`, `normalize_record()`), the shared resolver `resolve_selector()`, the tolerant enumeration `list_jobs_tolerant()` (records + unparseable count, the seam the workspace-scoped hooks and `status` read) and its cross-workspace sibling `iter_workspace_stores()` (the reap/roster sweep), the selection and liveness set — `worker_gone()` (the provably-gone predicate, no grace), `effective_status()` (deriving `STATUS_INTERRUPTED`), `is_active()`, `latest_key()`, `elapsed()` (the shared duration rendering), `render_job_row()` (the ONE bridge-first row helper for `status`, `reap` and the digests), `usable_pid()` — the session-scoped machinery (ADR 0004 reversed): the record fields `bridgeName`/`resumedFrom`/`lineageRoot`/`supervisedAt`/`supervisionTimeoutMs`, `SESSION_ID_VARIABLE` repointed to `CHINAMAX_SESSION_ID`, the `<data root>/sessions/` registry (`sessions_dir`, `write_session_registry`/`read_session_registry`/`remove_session_registry`/`iter_session_registrations`, `resolve_owner_process` walking `/proc` to the live Claude pid, `session_alive`/`session_is_alive` over the `worker_gone` family), `reap_session()` (SessionEnd → `cancelled`) / `reap_orphans()` (SessionStart → `interrupted`, plus stale-registry GC) / `reap_stale_supervision()` (the session hooks' Bridge-death sweep → `interrupted` reason `bridge terminated`, over this session's Bridge-owned still-`is_active` records whose heartbeat aged past `2×bound+10 s`, with `_supervision_is_stale`) returning `ReapResult`, the Bridge-supervision heartbeat `stamp_supervision()` (the `status --wait` stamp of `supervisedAt`/`supervisionTimeoutMs`, `max`-only, `touch=False`), and `SESSION_REAP_GRACE_S`/`SESSION_REAP_CONFIRM_S`/`SESSION_REAP_REASON`/`ORPHAN_REAP_REASON`/`SUPERVISION_REAP_REASON`/`SUPERVISION_STALE_MULTIPLIER`/`SUPERVISION_STALE_SLACK_S`; the `/proc` primitives (`parse_stat_fields`, `parse_pid_start_time`, `read_proc_stat`, `read_pid_start_time`, `read_comm`, `ProcessInfo`, `read_process`, `process_table`, `descendants`) and `terminate_tree()` (snapshot → SIGTERM by group → grace → re-scan → SIGKILL(`confirm_s`) → report survivors), the Git for Windows tool resolver `windows_tool_path()` (`GIT_FOR_WINDOWS_EXES` install-root probe first, then PATH — the ONE source both the setup Prerequisite probe (`doctor`) and the Runtime bash spawn resolve through), the steer-queue helpers (`write_steer()`/`list_steer_files()`/`steer_enqueued_at()`/`steer_now_ms()`, `STEER_CLOCK_VARIABLE`, `STEER_CONSUMED_DIRNAME`), the timing constants (`RECORD_THROTTLE_S` 2 s, `HEARTBEAT_INTERVAL_S` 30 s, `STALE_GRACE_S` 60 s, `TERMINATE_GRACE_S` 10 s, `POLL_INTERVAL_S` 2 s, `WAIT_TIMEOUT_DEFAULT_MS` 240 000 — the `status --wait` default — and `WAIT_TIMEOUT_MS` 900 000, the ceiling a larger `--timeout-ms` clamps to so the Bridge's 900 s long-poll is honored, `PRUNE_KEEP` 50), the 0700/0600 helpers (`make_dir`, `precreate`, `secure_file`), the log readers (`log_signature`, `tail_lines`), `escape_control()`/`summarize()`/`render_failure()`, and the two progress mechanisms `ProgressReporter` and `Heartbeat`.
- `spec.py` — `JobSpec` and the job-spec parser/validator: the public dispatch contract (`workspace`, `profile`, `prompt`, `transcript_path`, `result_path`, optional `write`/`model`/`job_id`/`seed_transcript`/`bash_timeout_s` and the supervision overrides `inactivity_timeout_s`/`ladder_attempts`/`backoff_base_s`/`backoff_cap_s`), plus `DEFAULT_BASH_TIMEOUT_S` (600 s).
- `confinement.py` — the tool-layer policy (ADR 0005): `ToolContext` (workspace realpath, posture, bash timeout), `resolve_in_workspace()`/`contained()` (component-wise realpath containment), `lex_command()` → `Stage` (the one shlex-based command lexer), and the two predicates over it — `denied_reason()` (the operator's hard bans) and `write_shaped_reason()` (read-only Jobs; redirection plus known writers such as `tee`, `touch`, `mv`, and `cp`).
- `profiles.py` — `Profile`, the shipped-plus-overlay resolution (`load_profiles`, `resolve_profile`, `format_available`) and API-key lookup from `~/.claude/model-keys.env` (`load_keys`, `resolve_key`).
- `doctor.py` — the Host-aware setup doctor: Claude keeps the diagnose→fix→re-diagnose flow, while Codex gets a genuinely non-mutating redacted preview with host-specific key/overlay/data/state/interpreter paths, bounded required-config diff, writability checks, deterministic consent digest, TOML-preserving atomic apply, backup, managed-agent compiler/sync, and collision warnings. The shared env/dependency/key/interpreter probes remain injectable and key values never enter reports or digests. Prerequisites (0.4.5): `prerequisite_status()` reports the per-Platform matrix (Linux/macOS `bash`+`miniconda`, Windows `git`/`bash`/`cygpath`+`miniconda`; conda resolved absolute via `_find_conda`, `~/miniconda3`→PATH, prepended to `_find_env_python`'s candidates), and `prerequisite_fixes()` builds the structured Rectification rows (`name`/`summary`/`commands`/`run_policy`/`shell`/`install_location`; Miniconda `latest`/HTTPS/no-checksum, Windows winget-or-PowerShell-fallback, linux package-manager, macOS brew) that `diagnose` stores under `prerequisite_fixes`, `render_report` prints, `missing_prerequisite_advice` summarizes, `run_setup` PAUSES on (Phase A: exit 1, no fixer), and `codex_setup_plan` binds into the consent digest — the Host adapter installs them only after operator approval; Python never installs a Prerequisite.
- `provider.py` — `sanitize_environment()` and `build_client()`: the `anthropic` SDK client for one Profile (bearer auth, `max_retries=0`, and a structured `httpx.Timeout` whose read budget backstops the inactivity watchdog).
- `liveness.py` — the supervision layer (ADR 0002): `LoopConfig` + `build_config()` (the inactivity/ladder/backoff knobs and the injected clock, sleeper and jitter seams), `InactivityWatchdog`, `run_attempt()` (one streaming call, all-or-nothing at `message_stop`), `classify()` with the transient/permanent table, `parse_retry_after()`, `backoff_sleep()`, `stream_with_ladder()` (the ladder itself), `RunFailure` (the terminal failure payload) and `emit_event()` (the structured progress reporter).
- `loop.py` — `run_loop()`: the streaming Messages tool-use loop, the system prompt, the tool-less-turn nudge, and the report_result termination rules. Builds the Job's posture-filtered registry and its `ToolContext` once, then routes every tool_use through them; each turn goes through `liveness.stream_with_ladder`. `_seed_history()` rehydrates a pre-populated Thread when the spec sets `seed_transcript`, in which case the seeded trailing user turn is sent without being re-appended and the spec's prompt is never appended as a second user message. The steer drain (when the worker passes a `steer_dir`): `_drain_steers()` runs at the top of EVERY iteration — reading `list_steer_files` in name order, folding each new steer's `STEER_MARKER`-prefixed text onto the outgoing user turn (`_attach_steer`), appending it to the Thread (transcript FIRST) and only THEN renaming into `consumed/` (`_consume_steer`), skipping any id already in the startup-seeded dedupe set — with the flush→rename crash window a test can hit via `_steer_abort_point`/`STEER_ABORT_VARIABLE`; `_sweep_undelivered()` logs any steer still queued at the terminal transition; `_steer_excerpt()` control-cleans a steer for its one log line. Also the closed progress vocabulary `PHASES` (`PHASE_STARTING`, `PHASE_CALLING_MODEL`, `PHASE_RUNNING_TOOL`, `PHASE_REPORTING`) and the optional `reporter` seam the supervisor mirrors into a Job's log and record.
- `policy.py` — worker-side Host-policy enforcement (ADR 0016), in three delimited sections. **Policy hooks**: settings/hook discovery for both Hosts (Claude managed→user→project→local `settings.json`; Codex `config.toml` `[[hooks.*]]` run-all), the `project_root` seam (nearest `.claude/`-or-`.git` ancestor), full native→Claude-canonical tool-name/payload `translate_tool`, apply_patch per-file `Edit` synthesis with RAW-segment re-slicing, bounded hook-process execution (reusing `tools/bash.py`'s `TailBuffer`/`_drain` and `state.terminate_tree`), fail-open decision parsing (`PreResult`/`StopResult`; ask→allow, crash/timeout→continue), and the PreToolUse/PostToolUse/Stop entrypoints. **Memory injection**: `discover_memory` (Host-global + ancestor chain + `@`-import resolution with fence/span scan and cycle guard, Claude memory-store exclusion), the FIXED versioned sentinel block (`build_memory_block`), and the structural `scan_injected_paths` seed-once scanner. **Worker MCP**: `discover_mcp_configs` (Claude `~/.claude.json`/project `.mcp.json`; Codex `config.toml [mcp_servers]`, nearest-scope-wins), `select_mcp_configs` (the pinned name list), and `WorkerMCP` (one background asyncio loop holding every stdio session, concurrent bounded connect, byte-stable schema snapshot, exact-name dispatch routing, bounded teardown). The `Policy` façade the loop drives, plus `canonical_json` (the shared doctor-precedent serializer). **Policy toggles** (0.7.0): the per-Host `settings.json` (`SETTINGS_FILENAME`) toggle API — `PolicySettings`/`PolicySettingsError`, the raising `load_policy_settings` (dispatch/exec), its tolerant twin `inspect_policy_settings` (status/setup), and the subset-update `write_policy_settings` (used by setup, via `state._write_file`); `Policy.build` gates each capability on these pinned toggles (default OFF). The Job-runtime layer NEVER raises — everything degrades fail-open, logged with a `[policy]` prefix — with the one exception that `load_policy_settings` raises `PolicySettingsError` at the dispatch/exec/setup boundary on a malformed toggle file.
- `transcript.py` — the Thread, over the versioned `{v, ts, kind}` record schema: `Transcript` (write-ahead JSONL writer, with `append_message()`, `append_steer()` (a replayable user turn carrying the steer id/enqueue-ts as metadata fields), the non-replayable `append_retry()`, and an `append` mode for a seeded run), `read_messages()` (the replay reader), `read_steer_ids()` (the drain's dedupe seed), the `STEER_MARKER` prefix, and the resume normalization — `read_repaired_messages()`, `repair_messages()` (a synthetic `tool_result` per unanswered `tool_use`, using `REPORTED_RESULT` for a terminal `report_result` and `INTERRUPTED_RESULT` otherwise), `coalesce_user_turns()` (folds a steer's own user record back into the turn the provider saw), `merge_follow_up()` (the follow-up joins a trailing user turn rather than doubling the role) and `write_messages()` (the dispatcher's copy).
- `hooks/` — the session-lifecycle + Bridge-enforcement entrypoints (session_start, session_end, stop, user_prompt, bridge_contract), reading state through the shared `state.list_jobs_tolerant`/`iter_workspace_stores`; SessionStart/Stop/UserPromptSubmit also run the shared `sweep_stale_supervision` (Bridge-death reap, 2026-07-31). See `hooks/repo-map.md`.
- `tools/` — the tool registry advertised to the provider. See `tools/repo-map.md`.
- `data/profiles.json` — the six shipped pro Profile rows (deepseek, mimo, glm, minimax, kimi, qwen) (shipped defaults; a dispatch may pin any model string the endpoint accepts), each `{name, base_url, model, api_key_env, request_extras}` — `request_extras` the always-on reasoning knob merged into every request; `max_tokens` is an optional per-row override of the code default.
